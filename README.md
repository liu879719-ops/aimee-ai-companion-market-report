# AI 陪伴赛道市场声音与行业洞察报告

## 文件结构

- `index.html`：报告首页，总览摘要和 6 个子报告入口。
- `user_voice.html`：AI 陪伴赛道用户声音报告。
- `user_profile.html`：AI 陪伴赛道用户画像报告。
- `industry_experience.html`：AI 陪伴赛道同行经验报告。
- `tech_implementation.html`：AI 陪伴赛道技术实现报告。
- `market_commercialization.html`：AI 陪伴赛道市场规模与商业化报告。
- `risk_compliance.html`：AI 陪伴赛道风险合规报告。
- `styles.css`：统一样式文件。
- `assets/evidence/`：报告中引用的原素材图片副本。

## 如何打开

直接双击或用浏览器打开 `index.html` 即可浏览。所有页面都是静态 HTML，不需要启动服务。

## 每个报告页面的用途

- 用户声音：整理用户需求、好评、差评、记忆、关系感、语音、流失、付费和隐私主题。
- 用户画像：按竞品拆解用户类型，并给出估算型综合画像分布图。
- 同行经验：基于桌面“从业者经验”截图提炼机会、难点、小团队打法和踩坑点。
- 技术实现：基于桌面“技术实现”截图拆解长期记忆、主动行为、人设稳定、语音和成本压力。
- 市场与商业化：基于桌面“市场规模/商业化”截图梳理需求趋势、商业化方式、付费意愿和会员权益。
- 风险合规：基于桌面“风险合规”截图梳理监管范围、隐私、未成年人、情绪依赖、内容安全、宣传和品牌风险。

## 资料不足时如何标注

报告中凡是当前项目文件夹或桌面专项资料夹未找到明确资料的地方，都标注为“现有资料不足，建议后续补充”。MoMood / Sweete 应用商店评论已读取并纳入分析；桌面“从业者经验、技术实现、市场规模/商业化、风险合规”四个文件夹已读取关键截图并纳入四个专题报告。仍不足的是 MoMood / Sweete 的原始截图、小红书截图、产品截图，以及可核验的正式行业规模数据、正式法务意见和完整技术方案文档。

## 来源标注原则

- 来自旧 HTML 报告的内容，标注为“旧竞品报告 / 竞品名”。
- 来自截图的内容，标注文件名和来源文件夹。
- 未经 OCR 的图片只标注来源和可能主题，不编造图片内具体文字。
- 用户画像占比为估算时，统一标注“不代表官方用户数据”。

## 图片素材存放位置

所有被页面引用的图片副本位于：

`assets/evidence/`

原始素材仍保留在项目资料库的 `00_inbox` 等目录中。

## 后续如何继续补充新资料

1. 将新增资料放入项目资料库，建议按竞品或主题分文件夹。
2. 对新增截图做 OCR 或人工摘要，补充到用户声音主题下。
3. 对 MoMood / Sweete 可继续补充 App Store 截图、小红书截图、产品截图，用来补强页面中的原素材证据墙。
4. 对市场规模、合规政策、技术方案等专项资料，建议单独建立对应文件夹，避免和评论截图混在一起。
5. 更新页面时保持“结论 + 证据 + 来源 + 对 Aimee 启发”的结构。
